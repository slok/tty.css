    Buttons

    Native actions and button-styled links, with variants, supported hosts, and disabled states.

    Button variants

    The default is primary. .secondary, .contrast, and .outline work on every supported button host.

    <div class="group">
  <button type="button">Primary</button>
  <button type="button" class="secondary">Secondary</button>
  <button type="button" class="contrast">Contrast</button>
  <button type="button" class="outline">Outline</button>
</div>

    Supported hosts

    Button styling applies to native button, submit/button/reset inputs, and a.button. Legacy a[role="button"] remains supported; arbitrary elements with that role are not styled. Use button for actions and a.button for navigation: the class preserves native link semantics and keyboard behavior. role="button" announces a button instead, but CSS does not add button keyboard behavior.

    Navigation guide
    <form action="#hosts">
  <div class="group">
    <button type="button">Button</button>
    <input type="submit" value="Submit">
    <input type="button" value="Input button" class="secondary">
    <input type="reset" value="Reset" class="outline">
    <a href="navigation.html" class="button contrast">Navigation guide</a>
  </div>
</form>

    Disabled states

    Use the native disabled attribute for buttons and button inputs. Links have no native disabled state: tty.css visually suppresses a.button[aria-disabled="true"] and legacy a[role="button"][aria-disabled="true"], but aria-disabled alone does not prevent activation. Remove href and block application handlers, or omit the unavailable link entirely.

    Unavailable destination
    <div class="group">
  <button type="button" disabled>Disabled button</button>
  <input type="submit" value="Disabled submit" disabled>
  <a role="button" aria-disabled="true">Unavailable destination</a>
</div>

    See control groups for connected or spaced actions, loading states for pending work, and links for ordinary navigation text.
