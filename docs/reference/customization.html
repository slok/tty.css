    Customize

    CSS variables

    Load tty.css first, then override its effective custom properties. The tables below reflect the variables actually consumed by the current stylesheet.

    Scope and themes

    Palette parameters live on :root and a root override applies across modes. For direct semantic color overrides, match each active selector you support: :root for light, :root[data-theme="dark"] for explicit dark, and :root[data-theme="auto"] inside prefers-color-scheme: dark for automatic dark. tty.css does not currently implement local, subtree themes.

    :root {
  --tty-accent: #ffd166;
  --tty-accent-hover: #ffc233;
  --tty-accent-fg: #2b1800;
}

:root[data-theme="dark"] {
  --tty-accent: #ffe08a;
  --tty-accent-hover: #ffeaad;
  --tty-accent-fg: #241400;
}

@media (prefers-color-scheme: dark) {
  :root[data-theme="auto"] {
    --tty-accent: #ffe08a;
    --tty-accent-hover: #ffeaad;
    --tty-accent-fg: #241400;
  }
}

    Recheck text, focus, control, selection, and status contrast in every theme after changing colors. See theme selection and accessibility responsibilities.

    Create a color palette

    Use the palette playground for generated colors, or Monokai for full overrides. The complete token tables are below.

    Color tokens

    tty.css requires OKLCH. The generated semantic roles use the parameter-derived formulas below, without hex fallbacks. Direct semantic overrides may use any CSS color format supported by your target browsers. Status colors have green, amber, and red bases; with the default palette, these bases are:

    TokenLight baseDark and auto-dark baseUsed for
    --tty-successoklch(50% 0.15625 150)oklch(80% 0.15625 150)Success badges/notices, valid states, inserted text, and optimum meters
    --tty-warningoklch(50% 0.15625 75)oklch(80% 0.15625 75)Warning badges/notices and suboptimum meters
    --tty-dangeroklch(50% 0.15625 25)oklch(80% 0.15625 25)Danger badges/notices, invalid states, deletion, and poor meters

    Browsers with color-mix() harmonize each base with a 25% accent-hue tint in OKLab at the same lightness. Other OKLCH-capable browsers keep the generated base. Public status overrides use the same mode selectors as other semantic tokens; full overrides such as Monokai remain authoritative.

    Public palette parameters

    These defaults apply across all modes. Override them on :root after tty.css; no support guard is needed. Direct semantic token overrides remain supported and can be mixed with parameters.

    ParameterDefault (all modes)Role mapping
    --tty-accent-hue65Hue of accents, links, general focus, and selection; a bounded tint for statuses
    --tty-accent-chroma0.125Chroma of accent roles, with role-specific factors; bounded intensity and tint for statuses
    --tty-neutral-hue260Hue of canvas, surfaces, text, borders, code, control focus, and shadows
    --tty-neutral-chroma0.025Chroma of those neutral roles, with role/mode-specific factors

    Status hues stay recognizable even with zero accent chroma; SVG icon images remain independent of the parameters. Arbitrary hue/chroma choices are not guaranteed accessible; test each mode and state. See the Colors guide for parameter-only, direct, and mixed palettes.

    Effective OKLCH role formulas

    Every row evaluates to oklch(L C H). Here A means var(--tty-accent-chroma), N means var(--tty-neutral-chroma), and hue is the corresponding public hue parameter. Multiplication denotes calc(). These describe the implementation, not additional public knobs.

    Light (including an omitted theme attribute) uses the light column. Explicit dark uses the dark column. Auto uses light unless prefers-color-scheme: dark matches, when it uses dark. Modes select internal --_tty-* lightness values and neutral chroma factors; those internal values are not public API.

    Semantic tokenL light / darkC light / darkH parameter
    --tty-bg98.5% / 18%N × 0.2 / N × 1.2neutral hue
    --tty-surface100% / 23%N × 0 / N × 1.2neutral hue
    --tty-surface-muted96.5% / 27%N × 0.4 / N × 1.6neutral hue
    --tty-fg21% / 98%N × 1.6 / N × 0.2neutral hue
    --tty-fg-muted48% / 78%N / Nneutral hue
    --tty-border85% / 43%N / Nneutral hue
    --tty-border-strong21% / 98%N × 1.6 / N × 0.2neutral hue
    --tty-accent83% / 83%A / Aaccent hue
    --tty-accent-hover78% / 88%A / Aaccent hue
    --tty-accent-fg27% / 23%A × 0.32 / A × 0.32accent hue
    --tty-link47% / 85%A / Aaccent hue
    --tty-link-hover40% / 80%A / Aaccent hue
    --tty-selection90% / 40%A × 0.6 / A × 0.6accent hue

    Status formulas

    The status bases use L = 50% in light and print, or 80% in dark/auto-dark; C = clamp(0.1, 0.1 + A × 0.45, 0.18); and fixed hues of 150 (success), 75 (warning), and 25 (danger). The chroma floor keeps muted and zero-chroma accent themes from washing out status colors.

    Where color-mix() is supported, each effective status is color-mix(in oklab, base 75%, tint). The tint uses the same status lightness, clamp(0, A × 1.5, C) chroma, and the accent hue. Capping tint chroma bounds its hue influence. A zero-chroma accent adds an achromatic tint, not a new hue. Override public status tokens rather than these internal calculations when your palette needs different semantics.

    Typography and font policy

    TokenDefaultUsed for
    --tty-font"JetBrains Mono", ui-monospace, SFMono-Regular, Menlo, Monaco, Consolas, "Liberation Mono", "Courier New", monospaceBody, controls, code, and component headings
    --tty-font-displayvar(--tty-font)Page headings and reading-layout headings
    --tty-reading-width72chMaximum width of paragraphs and other reading text

    tty.css names JetBrains Mono first but does not load fonts. It uses JetBrains Mono only when already installed and otherwise follows the system monospace fallback stack.

    Override both font tokens when body and display text should differ. Supply complete fallback stacks, verify all required weights, and test control sizing, code, wrapping, and layout in fallback fonts. A ch-based reading width changes with the selected font.

    :root {
  --tty-font: "IBM Plex Mono", ui-monospace, monospace;
  --tty-font-display: "IBM Plex Sans", system-ui, sans-serif;
  --tty-reading-width: 68ch;
}

    --tty-shadow-y0.5remVertical decorative frame shadow

    --tty-shadow-opacity0.6; 1 for .strong-shadowFrame-shadow opacity

    --tty-shadow-pattern-size4px 4pxMask tile size, not offset; use 3px 3px for Fine

    Changing a dimension can affect many components at once. Keep border widths non-negative, preserve usable target sizes, and check narrow layouts before shipping.

    --tty-spinner-size is an optional override, resolved on the spinner pseudo-element with a 2em fallback rather than a root declaration. Set a positive CSS length on :root, a wrapper, or a busy element; see the spinner size examples. Large spinners may increase line and button height.

    Set --tty-grid-min on an individual grid for a local override; see the live grid example.

    <div class="grid" style="--tty-grid-min: 14rem">
  <article><h3>Primary</h3><p>Healthy</p></article>
  <article><h3>Replica</h3><p>Healthy</p></article>
</div>
    :root {
  --tty-container: 80rem;
  --tty-radius: 0;
  --tty-frame-width: 2px;
  --tty-shadow-x: 0.35rem;
  --tty-shadow-y: 0.35rem;
  --tty-control-shadow-size: 0.1rem;
  --tty-control-height: 2.75rem;
}

    For a component-scoped adjustment, override --tty-frame-width, --tty-shadow-x, and --tty-shadow-y on an application class instead of :root. These also work with the optional frame treatments; double borders use 3× the frame width, while strong shadows keep the configured offsets.

    The four mask-shadow tokens are optional overrides, not required :root declarations. They are shared by articles, fieldsets, tabs, table wrappers, and dialogs. Their defaults resolve on each shadow pseudo-element so local border colors are respected, and explicit overrides also win on .strong-shadow. SVG masks supply shapes only; CSS supplies color. For a custom --tty-shadow-pattern: url(...), the SVG alpha defines transparency. See texture examples.

    The two progress pattern tokens are separate optional overrides, not aliases of the shadow tokens. Their defaults resolve where consumed, with no :root aliases. Set them on progress.textured to customize its mask; SVG alpha supplies the shape while CSS color supplies the currentColor fill. The default Dense mask matches frame shadows but is configured independently. See the native progress example.

    On .overflow-auto table wrappers, frame treatments style the table frame and its shadow within the wrapper padding. Dropdown and tooltip overlays are shadowless and do not support frame treatments; dropdown lists need no wrapper. Small solid control shadows, radio states, and validation treatments remain intentional.

    --tty-space is not defined or consumed by the current stylesheet. It is not part of the effective customization API, and overriding it has no effect; use ordinary application spacing rules instead.

    Icon library

    The docs appearance button uses Pixel Icon Library's brightness-high, moon, and laptop SVGs, served locally as a currentColor sprite. Their geometry is unchanged; see the source and license notice. These are documentation assets, not a framework icon bundle.

    tty.css does not include an icon library. For a matching pixel style, try Pixel Icon Library by HackerNoon. Follow their usage guide and license requirements.

    Icon tokens

    TokenDefaultUsed for
    --tty-icon-searchEmbedded 16×16 SVG data URLSearch inputs
    --tty-icon-dateEmbedded 16×16 SVG data URLDate, month, and week inputs
    --tty-icon-timeEmbedded 16×16 SVG data URLTime inputs
    --tty-icon-datetimeEmbedded 16×16 SVG data URLLocal date-time inputs

    These icons are decorative CSS backgrounds; control labels provide meaning. Their SVG strokes remain fixed at #526174 in light and #aab7c8 in dark/auto-dark; changing palette parameters or --tty-fg-muted does not recolor the images. Override them with a CSS url(), including a percent-encoded data URL if embedding SVG. Match the 16×16 view box and test light, dark, and disabled states. Firefox and forced-colors mode intentionally use native picker presentation for date and time controls.

    :root {
  --tty-icon-search: url("/assets/search.svg");
  --tty-icon-date: url("/assets/calendar.svg");
  --tty-icon-time: url("/assets/clock.svg");
  --tty-icon-datetime: url("/assets/date-time.svg");
}

    Low-specificity overrides

    Most framework selectors use :where(), so an application class normally wins without !important. Load overrides after tty.css and target the smallest stable application hook. Some structural selectors and composition classes have normal specificity, so inspect the actual rule when an override does not win.

    .billing-card {
  border-style: dashed;
}

button.danger {
  background: var(--tty-danger);
  color: var(--tty-surface);
}

.settings-form input {
  border-radius: 0;
}

    Avoid overriding generated internals such as browser-specific range and meter pseudo-elements unless your product owns the resulting cross-browser test matrix.
