    Getting started

    Themes

    Light is the default. Select dark explicitly or let the operating-system preference choose the palette's light or dark mode.

    Theme behavior

    Without a data-theme attribute, the :root light palette applies. The dark palette applies only to data-theme="dark". Automatic mode starts from the light palette and switches to dark inside prefers-color-scheme: dark.

    Each mode also sets the browser-facing color-scheme property, so compatible native controls use the corresponding light or dark appearance.

    The docs bar separates the theme selector (a named palette such as Default or Sakura) from the appearance icon button (cycles Light, Dark, or Auto, applied through data-theme). The icon shows a sun, moon, or laptop for the system setting; its accessible name and tooltip identify the current appearance and the next choice. Both choices are saved across docs and examples. These controls are docs-only JavaScript; the framework itself still needs none.

    Use Theme in the bar to try the shared presets, or the palette playground to adjust their parameters. The Colors guide explains direct overrides and contrast checks; the CSS variables reference lists the parameters and exact color formulas.

    The Monokai example demonstrates full color overrides with a dark palette and a light companion.

    Use the light theme

    Omit the attribute or select light explicitly. An explicit value is useful when an application stores a preference.

    <html lang="en" data-theme="light">

    Use the dark theme

    Set the attribute on the document root. tty.css theme selectors do not theme an individual descendant subtree.

    <html lang="en" data-theme="dark">

    Follow the system

    Automatic mode follows prefers-color-scheme. It needs no JavaScript and updates when the system preference changes.

    <html lang="en" data-theme="auto">

    Control themes with JavaScript

    Change document.documentElement.dataset.theme to apply a user choice. Persist a value only after an explicit choice; otherwise, leave auto in control. This complete example cycles through the three supported values, stores the selection, and keeps the button label accessible.

    <button type="button" id="theme-toggle">Theme: light</button>
<script>
  const root = document.documentElement;
  const button = document.querySelector("#theme-toggle");
  const themes = ["light", "dark", "auto"];
  const storedTheme = localStorage.getItem("theme");

  if (storedTheme && themes.includes(storedTheme)) {
    root.dataset.theme = storedTheme;
  }

  function updateThemeButton() {
    const theme = root.dataset.theme || "light";
    button.textContent = `Theme: ${theme}`;
    button.setAttribute("aria-label", `Current theme: ${theme}. Change theme`);
  }

  button.addEventListener("click", () => {
    const current = root.dataset.theme || "light";
    const next = themes[(themes.indexOf(current) + 1) % themes.length];
    root.dataset.theme = next;
    localStorage.setItem("theme", next);
    updateThemeButton();
  });

  updateThemeButton();
</script>

    The theme switcher in these documentation pages is progressive enhancement. The palettes themselves remain CSS-only.
