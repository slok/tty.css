Customize

Colors

Keep the HTML and components; change their palette with a separate, variable-only stylesheet. Hex and OKLCH both work with the existing tty.css color tokens.

Load a palette after tty.css

<link rel="stylesheet" href="tty.css">
<link rel="stylesheet" href="forest-theme.css">

No component selectors or new classes are needed. Unspecified tokens retain the framework defaults. Find the complete color token table in CSS variables, and use Themes to choose a mode rather than a palette.

Start with hex: Forest

Set the accent background, hover background, and foreground together. Links need their own readable colors on the page background. This small Forest excerpt covers light, explicit dark, and automatic dark:

/* forest-theme.css: light defaults, including auto-light */
:root {
  --tty-accent: #bbf7d0;
  --tty-accent-hover: #86efac;
  --tty-accent-fg: #14351f;
  --tty-link: #166534;
  --tty-link-hover: #14532d;
  --tty-focus: #15803d;
}

:root[data-theme="dark"] {
  --tty-accent: #86efac;
  --tty-accent-hover: #bbf7d0;
  --tty-accent-fg: #14351f;
  --tty-link: #86efac;
  --tty-link-hover: #bbf7d0;
  --tty-focus: #86efac;
}

@media (prefers-color-scheme: dark) {
  :root[data-theme="auto"] {
    --tty-accent: #86efac;
    --tty-accent-hover: #bbf7d0;
    --tty-accent-fg: #14351f;
    --tty-link: #86efac;
    --tty-link-hover: #bbf7d0;
    --tty-focus: #86efac;
  }
}

Override every active root selector you support; tty.css does not implement local subtree themes. Select modes with <html data-theme="light">, <html data-theme="dark">, or <html data-theme="auto">. Omitting the attribute also uses light.

Build related colors with OKLCH

oklch(L C H) separates lightness, chroma, and hue:

  • L: perceptual lightness, from 0 (black) to 1 (white), also written as 0% to 100%.
  • C: chroma, or color intensity. 0 is neutral; higher values are more colorful, with the usable range depending on lightness, hue, and display gamut.
  • H: hue angle around the color wheel, from 0 to 360 degrees.

Holding L steady while changing H gives more predictable, approximately similar perceived brightness than changing an RGB or HSL hue. It does not preserve exact contrast or automatically choose accessible foregrounds.

The Ocean and Plum examples share application-owned --palette-hue and --palette-chroma knobs. These are helpers defined by the example stylesheets, not tty.css framework API. They feed the existing --tty-* tokens:

/* Load after tty.css. Keep framework defaults without OKLCH support. */
@supports (color: oklch(0.5 0.1 250)) {
  :root {
    --palette-hue: 250;
    --palette-chroma: 0.08;
    --tty-accent: oklch(0.85 var(--palette-chroma) var(--palette-hue));
    --tty-accent-hover: oklch(0.80 var(--palette-chroma) var(--palette-hue));
    --tty-accent-fg: oklch(0.24 0.03 var(--palette-hue));
    --tty-link: oklch(0.40 var(--palette-chroma) var(--palette-hue));
  }

  :root[data-theme="dark"] {
    --tty-accent: oklch(0.80 var(--palette-chroma) var(--palette-hue));
    --tty-accent-hover: oklch(0.85 var(--palette-chroma) var(--palette-hue));
    --tty-accent-fg: oklch(0.24 0.03 var(--palette-hue));
    --tty-link: oklch(0.80 var(--palette-chroma) var(--palette-hue));
  }

  @media (prefers-color-scheme: dark) {
    :root[data-theme="auto"] {
      --tty-accent: oklch(0.80 var(--palette-chroma) var(--palette-hue));
      --tty-accent-hover: oklch(0.85 var(--palette-chroma) var(--palette-hue));
      --tty-accent-fg: oklch(0.24 0.03 var(--palette-hue));
      --tty-link: oklch(0.80 var(--palette-chroma) var(--palette-hue));
    }
  }
}

This is an excerpt, not a full palette. The downloadable examples also coordinate hover links, focus, surfaces, and other color roles. Ocean uses hue 245; Plum uses 315, with the same chroma and lightness values. Instead of handpicking each shade again, change one parameter:

/* Application CSS loaded after ocean-theme.css */
:root {
  --palette-hue: 315;
}

The neutral surfaces use lower chroma than accents, and dark mode changes the lightness values rather than just inverting colors. Inspect and retest the resulting palette whenever you adjust these parameters.

Gamut and safe fallbacks

Some OKLCH combinations lie outside a display's color gamut. Browsers gamut-map them to representable colors, which can alter the intended appearance. Prefer modest chroma, inspect on sRGB displays, and recheck contrast after hue or chroma changes.

Guard the token overrides with @supports (color: oklch(0.5 0.1 250)), as above. Unsupported browsers then keep tty.css defaults. For a branded fallback, put hex overrides for each supported light/dark/auto selector before that guarded block.

Do not rely on duplicate declarations such as --tty-link: #166534; --tty-link: oklch(...); for fallback. Custom properties accept arbitrary token streams, so an unsupported color function can win the cascade and only become invalid when consumed by color: var(--tty-link). The earlier hex declaration is not restored then. Testing a custom-property declaration itself is not a useful color-support check.

Check the whole palette

Test light, dark, and both system preferences in auto mode. Measure normal and hovered text contrast, including muted text, selections, code, and accent-button labels. Check visible keyboard focus, control boundaries, disabled and validation states, print output, and narrow layouts. Keep status meaning independent of hue. See accessibility responsibilities.
