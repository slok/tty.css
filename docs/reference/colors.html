    How the parameters work

    OKLCH separates lightness, chroma, and hue. Hue chooses the color; chroma sets its intensity. tty.css chooses lightness for each role and mode, making related shades easier to create.

    Accent parameters control buttons, links, selection, and general focus. Neutral parameters control surfaces, text, borders, code, and control focus. SVG icons remain independent.

    Status colors start from green, amber, and red bases. Accent chroma adjusts their intensity within bounds, and browsers with color-mix() add a 25% equal-lightness accent tint in OKLab. This shifts their shade toward the palette without replacing their semantic hues. Light and dark modes choose contrasting lightness values. Slate and zero-chroma accent palettes retain colored statuses instead of turning them gray; meaningful labels must still carry the status.

    The same generated --tty-success, --tty-warning, and --tty-danger tokens style badges, notices, validation, inserted/deleted text, and meters. Override these tokens directly for a fully custom status palette, including deliberately monochrome statuses. See the status bases and formulas.

    High chroma may exceed your display's gamut, so the browser maps colors to what it can show.

    See parameter defaults, all color tokens, and accessibility guidance.

    Need finer control? Full overrides

    If the parameters aren't enough, override individual tokens such as --tty-bg or --tty-accent. You can pin just one color or define a full palette, as Monokai does. Match the mode selectors in the variable reference.
