Customize

Colors

Keep the HTML and components; change their palette with a separate, variable-only stylesheet. Use framework palette parameters for related colors, or override semantic color tokens for exact control.

Load a palette after tty.css

<link rel="stylesheet" href="tty.css">
<link rel="stylesheet" href="forest-theme.css">

No component selectors or new classes are needed. Unspecified tokens retain the framework defaults. Find the color token reference in CSS variables, and use Themes to choose a mode rather than a palette.

Start with hex: Forest

Set the accent background, hover background, and foreground together. Links need their own readable colors on the page background. This small Forest excerpt covers light, explicit dark, and automatic dark:

/* forest-theme.css: light defaults, including auto-light */
:root {
  --tty-accent: #bbf7d0;
  --tty-accent-hover: #86efac;
  --tty-accent-fg: #14351f;
  --tty-link: #166534;
  --tty-link-hover: #14532d;
  --tty-focus: #15803d;
}

:root[data-theme="dark"] {
  --tty-accent: #86efac;
  --tty-accent-hover: #bbf7d0;
  --tty-accent-fg: #14351f;
  --tty-link: #86efac;
  --tty-link-hover: #bbf7d0;
  --tty-focus: #86efac;
}

@media (prefers-color-scheme: dark) {
  :root[data-theme="auto"] {
    --tty-accent: #86efac;
    --tty-accent-hover: #bbf7d0;
    --tty-accent-fg: #14351f;
    --tty-link: #86efac;
    --tty-link-hover: #bbf7d0;
    --tty-focus: #86efac;
  }
}

Override every active root selector you support; tty.css does not implement local subtree themes. Select modes with <html data-theme="light">, <html data-theme="dark">, or <html data-theme="auto">. Omitting the attribute also uses light.

The full stylesheet also coordinates canvas, surfaces, text, borders, selection, code, control focus and shadows, plus print overrides. Embedded SVG input icons use separate icon tokens.

Level 1: framework palette parameters

oklch(L C H) separates lightness, chroma, and hue:

  • L: perceptual lightness, from 0 (black) to 1 (white), also written as 0% to 100%.
  • C: chroma, or color intensity. 0 is neutral; higher values are more colorful, with the usable range depending on lightness, hue, and display gamut.
  • H: hue angle around the color wheel, from 0 to 360 degrees.

Holding L steady while changing H gives more predictable, approximately similar perceived brightness than changing an RGB or HSL hue. It does not preserve exact contrast or automatically choose accessible foregrounds.

tty.css requires OKLCH and exposes four public parameters: --tty-accent-hue: 65, --tty-accent-chroma: 0.125, --tty-neutral-hue: 260, and --tty-neutral-chroma: 0.025. The framework derives semantic colors from them without support guards or generated-role hex fallbacks. A single hue change brands accents, links, general focus, and selection without changing the neutral palette:

/* Load after tty.css; applies in light, dark, and auto. */
:root {
  --tty-accent-hue: 315;
}

Neutral hue and chroma independently control canvas, surfaces, text, borders, code, control focus, and control shadows. Ocean's complete stylesheet is just these parameter overrides; Plum uses 315 for both hues instead:

/* ocean-theme.css */
:root {
  --tty-accent-hue: 245;
  --tty-accent-chroma: 0.1;
  --tty-neutral-hue: 245;
  --tty-neutral-chroma: 0.025;
}

Light mode chooses light canvases and dark text; dark mode chooses dark canvases and light text. Modes select internal lightness values and neutral chroma factors, not a single saturation setting. Auto selects the same light or dark factors according to the system preference. The --_tty-* values are implementation details, not public API; see the exact role formulas.

Status colors (--tty-success, --tty-warning, and --tty-danger) remain independent, fixed hex colors per mode. Embedded SVG icon image tokens are unchanged and do not recolor from palette parameters. Hue and chroma changes do not guarantee an accessible arbitrary palette; inspect and retest every adjustment.

Level 2: semantic overrides, alone or mixed

The Forest example above directly overrides semantic tokens, and its full stylesheet remains a complete hex palette. Existing root/theme selectors still work. You can also derive most colors from parameters and pin individual roles; the following fixes the link color in every mode while keeping the rest parameter-driven:

:root {
  --tty-accent-hue: 315;
  --tty-neutral-hue: 260;
  --tty-link: #6b21a8;
}

:root[data-theme="dark"] {
  --tty-link: #e9d5ff;
}

@media (prefers-color-scheme: dark) {
  :root[data-theme="auto"] {
    --tty-link: #e9d5ff;
  }
}

Direct overrides may use any CSS color format supported by your target browsers, including hex, RGB, HSL, or OKLCH. Neither parameters nor direct OKLCH colors need support guards within tty.css's supported target. Overrides win by the normal cascade when loaded after tty.css with the matching selector specificity. Coordinate related roles such as link hover and focus, and test contrast; overriding a semantic token does not change the parameters or other roles.

Gamut and chroma

Some OKLCH combinations lie outside a display's color gamut. Browsers gamut-map them to representable colors, which can alter the intended appearance. Prefer modest chroma, inspect on sRGB displays, and recheck contrast after hue or chroma changes.

Check the whole palette

Test light, dark, and both system preferences in auto mode. Measure normal and hovered text contrast, including muted text, selections, code, and accent-button labels. Check visible keyboard focus, control boundaries, disabled and validation states, print output, and narrow layouts. Keep status meaning independent of hue. See accessibility responsibilities.
