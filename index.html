A small, class-light CSS framework for technical interfaces. Write meaningful HTML, add one stylesheet, and get a responsive interface with terminal character.

One file. Native elements.

01 / Install

Download tty.css and link it in your document.

<link rel="stylesheet" href="tty.css">

02 / Write HTML

No component library and no generated class soup.

<main>
  <h1>Search everything</h1>
  <button>Run query</button>
</main>

03 / Choose a theme

Light is the default. Dark and system modes use one attribute.

<html data-theme="dark">
<html data-theme="auto">

Why semantic HTML?

Native elements provide keyboard behavior, useful structure, and durable defaults before CSS arrives.

Can I override the styles?

Yes. Most framework selectors use :where(), keeping their specificity at zero.

Dialog

Native dialogs inherit the same surface, border, and hard shadow. Opening and closing remains an application concern, so tty.css does not ship JavaScript. 

<dialog>
  <h3>Delete namespace?</h3>
  <p>This action cannot be undone.</p>
  <button>Confirm</button>
</dialog>

Focused customization

Override a compact public API instead of fighting component-specific selectors. 

:root {
  --tty-font: "IBM Plex Mono", monospace;
  --tty-font-display: "IBM Plex Sans", sans-serif;
  --tty-bg: #fffdf5;
  --tty-fg: #172554;
  --tty-accent: #fde047;
  --tty-container: 80rem;
  --tty-radius: 0;
  --tty-shadow-x: 0.5rem;
  --tty-shadow-y: 0.5rem;
}
